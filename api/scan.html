为移动设备提供库存流转操作功能

GET/POST /api/scan.php
扫描操作API为移动设备提供库存流转操作功能，移植自 mobile/scan.php 的功能。 支持包信息查询、目标库位信息获取和库存流转操作。

主要功能

  • 获取包信息
  • 获取目标库位信息并判断操作类型
  • 执行库存流转操作

认证方式

使用Bearer Token认证，需要在请求头中添加Authorization字段：

Authorization: Bearer {token}

获取Token方式：通过 auth.php接口 登录获取

GET /api/scan.php?action=get_package_info
通过包号获取包的详细信息，包括当前库位、数量、状态等信息。

请求参数

参数名 类型 必填 描述 示例
action string 是 固定值：get_package_info get_package_info
package_code string 是 包编号 YP20240001

请求示例

// 请求头
Authorization: Bearer your-token-here

// 查询包信息
GET /api/scan.php?action=get_package_info&package_code=YP20240001

// 移动端二维码扫描场景
GET /api/scan.php?action=get_package_info&package_code=YP20240001

响应示例

GET /api/scan.php?action=get_target_info
获取目标库位架信息并自动判断操作类型，系统根据当前区域和目标区域自动判断操作类型。

请求参数

参数名 类型 必填 描述 示例
action string 是 固定值：get_target_info get_target_info
target_rack_code string 是 目标库位架编码 R001
current_area_type string 否 当前区域类型（用于判断操作类型） storage
base_name string 否 基地名称 总部基地

请求示例

// 请求头
Authorization: Bearer your-token-here

// 获取目标库位信息
GET /api/scan.php?action=get_target_info&target_rack_code=R001¤t_area_type=storage&base_name=总部基地

// 移动端二维码扫描场景
GET /api/scan.php?action=get_target_info&target_rack_code=R001

响应示例

{ "code": 200, "message": "获取成功", "timestamp": 1698765432, "data": { "rack_code": "R001", "rack_name": "A区货架", "area_type": "storage", "base_name": "总部基地", "transaction_type": "location_adjust", "transaction_name": "库位调整" } }

操作类型说明

操作类型 描述 适用场景
purchase_in 采购入库 新包入库到库存区
usage_out 领用出库 从库存区领用到加工区
return_in 归还入库 从加工区归还到库存区
scrap 报废 从加工区报废到报废区
location_adjust 库位调整 在库存区内调整库位

POST /api/scan.php?action=location_adjust
跨基地转移API：将玻璃包从一个基地转移到另一个基地的临时库位，系统自动获取目标库位。

请求参数（JSON格式）

参数名 类型 必填 描述 示例
package_code string 是 包号 NT251226001
target_base_id integer 是 目标基地ID 3

注意：系统会自动获取目标基地的第一个可用临时库位，无需手动指定库位编码。

请求示例

// 请求头
Authorization: Bearer your-token
Content-Type: application/json

// 请求体
{ "package_code": "NT251226001", "target_base_id": 3 }

响应示例

{ "code": 200, "message": "库位调整操作成功完成！", "timestamp": 1735276800, "data": { "package_code": "NT251226001", "current_pieces": 35, "from_base": { "id": 2, "name": "新丰基地" }, "to_base": { "id": 3, "name": "金鱼基地" }, "target_temp_rack": { "id": 5, "code": "JY-T-临时区", "name": "临时区" }, "transaction_type": "location_adjust", "operator": "管理员" } }

业务规则

  • 权限验证：只有库管可以执行跨基地转移
  • 跨基地限制：目标基地必须与当前基地不同
  • 自动库位：系统自动获取目标基地的第一个可用临时库位(area_type = 'temporary')
  • 转移数量：自动使用包的当前片数
  • 备注生成：自动生成格式为"从{源基地名}转来"的备注
  • 顺序号调整：源库位和目标库位的包顺序号都会自动重新整理

JavaScript示例

// 跨基地转移操作
async function executeLocationAdjust(packageCode, targetBaseId) {
const response = await fetch('/api/scan.php?action=location_adjust', {
method: 'POST',

'Authorization': 'Bearer ' + getToken(),
'Content-Type': 'application/json'
},
body: JSON.stringify({
package_code: packageCode,
target_base_id: targetBaseId
})
});
return await response.json();
}

// 使用示例
executeLocationAdjust('NT251226001', 3)
.then(result => {
if (result.code === 200) {
console.log('转移成功:', result.data);
} else {
console.error('转移失败:', result.message);
}
})
.catch(error => console.error('请求失败:', error));
POST /api/scan.php
执行库存流转操作，支持采购入库、领用出库、归还入库、报废和库位调整等操作类型。

请求参数（JSON格式）

参数名 类型 必填 描述 示例
package_code string 是 包编号 YP20240001
target_rack_code string 是 目标库位架编码 R001
quantity integer 是 操作数量（必须≥0） 100
transaction_type string 是 操作类型（见上表） usage_out
scrap_reason string 否 报废原因（仅报废操作需要） 破损严重
notes string 否 备注信息 领用出库
all_use boolean 否 是否全部用完（勾选时数量自动设为0表示完全使用） true

请求示例

// 请求头
Authorization: Bearer your-token-here
Content-Type: application/json

// 请求体
{ "package_code": "YP20240001", "target_rack_code": "R001", "quantity": 100, "transaction_type": "usage_out", "scrap_reason": "", "notes": "领用出库", "all_use": false }

// 全部用完示例（勾选全部使用时）
{ "package_code": "YP20240001", "target_rack_code": "R001", "quantity": 0, "transaction_type": "usage_out", "scrap_reason": "", "notes": "整包领用", "all_use": true }

响应示例

{ "code": 200, "message": "领用出库操作成功完成！", "timestamp": 1698765432, "data": { "package_code": "YP20240001", "target_rack_code": "R001", "quantity": 100, "transaction_type": "usage_out", "operator": "张三" } }

错误响应

{ "code": 400, "message": "操作数量不能超过包裹现有片数：50", "timestamp": 1698765432 }

错误码说明

错误码 描述 解决方案
200 请求成功 -
400 请求参数错误 检查参数格式和必填项
401 认证失败 检查令牌有效性
404 资源未找到 检查包号或库位架是否存在
405 请求方法不允许 使用正确的HTTP方法
500 服务器内部错误 联系系统管理员

使用流程示例

完整的扫描操作流程

  1. 获取包信息：扫描包二维码获取包信息
  2. 获取目标库位信息：扫描目标库位架二维码
  3. 自动判断操作类型：系统根据当前区域和目标区域自动判断操作类型
  4. 执行操作：确认信息后执行库存流转操作

移动端集成示例

使用建议

  • 二维码扫描：建议在移动端实现二维码扫描功能，提高操作效率
  • 操作验证：系统会自动验证操作权限和业务规则，确保数据一致性
  • 数量控制：操作数量不能超过包的现有片数，确保库存准确性
  • 报废操作：报废操作必须填写报废原因，便于追溯管理
  • 跨域支持：支持CORS跨域请求，可直接在移动端调用
  • 错误处理：建议实现完善的错误处理机制，提供友好的用户提示
